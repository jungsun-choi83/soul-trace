## 0. Cursor 실행 지침 — 가장 먼저

1. 저장소 전체를 읽고 `docs/`에 `SOULTRACE_BASELINE_AUDIT.md` 작성: 현재 구현/기능 플래그/미구현/DB 적용 여부/운영 영향/테스트 실패를 **증거 경로와 함께** 분류한다. 코드 존재만으로 서비스 정상 작동이라고 판단하지 않는다.
2. `.cursor/rules/auto-commit-deploy.mdc` 기존 버전은 작업 종료 시 `master` 푸시와 Vercel production 배포를 요구하므로 위험하다. 동봉한 안전 규칙으로 교체한 뒤 작업한다. **명시적 승인 없는 운영 DB 변경·운영 배포·master 병합 금지.** 변경은 새 feature 브랜치에서 진행한다.
3. 전체 기능을 한 번에 재작성하지 말 것. 기존 편지 생성, 계정 인증, 1회성 handoff, 기존 저장 파일·영구 링크, 사진/영상 업로드 경로를 유지하고 **additive migration + 점진적 전환**으로 진행한다.
4. 각 단계에서 `npm test`, `npm run lint`, `npm run build` 실행, 통과/실패를 파일별로 보고. 테스트 실패가 기존인지 신규인지 구분. `.env` 값·사용자 미디어·이메일·GPS 원시 좌표를 로그에 남기지 않는다.
5. 기획 가설과 확정 기능을 구분: 제안 판매가는 실제 결제 가격이 아니다. 결제/환불/호스팅 약관 준비 전 상품 결제 버튼을 운영에 노출하지 않는다.

## 1. 목표와 소비자가 구매하는 이유

**포지셔닝:** '함께하는 오늘을 기록하고, 함께했던 시간을 오래 간직하는 곳.'

### 살아 있는 반려동물
- 사용 동기: 사진이 쌓일수록 '작년 오늘', '이번 달 우리 아이', '첫 산책', '가족이 함께 남긴 이야기'처럼 **자동으로 읽기 쉬운 결과물**을 얻는다.
- 첫 이용 1~2분 내: 회원가입/반려동물 생성 → 사진 1장 업로드 → 날짜가 표시된 기억 카드 확인. 긴 편지 설문, 유료 상품, AI 영상 제작을 강제하지 않는다.
- 재방문: 기록 타임라인, 즐겨찾기, 월간 회고, 선택한 기념일 알림, 가족 공동 기록. 기본 알림은 선택 사항. 카운트다운/출석 강요 금지.
- 차별점: 단순 파일 저장이 아니라 기록을 **정돈된 이야기로 재구성**. AI가 실제 없었던 사건을 만들어내지 않도록 사용자 자료를 근거로 사용한다.

### 떠나보낸 반려동물
- 사용 동기: 무리 없이 기억을 보관하고, 마음이 내킬 때 보고, 고마웠던 일을 정리하고, 필요하면 가족과 공유한다.
- 원하지 않는 AI 편지·모션·기념일 알림·'오늘도 기록하세요' 푸시는 기본 OFF. 추모 모드 사용자가 직접 켠다.
- `감정 기록(비공개)` 및 `하고 싶었던 말 쓰기`는 선택형. 가족 위로 메시지 수신 여부도 개별 동의.
- '우울증 치료', '슬픔 극복 보장', '떠난 아이와 실제 대화', 'AI가 아이의 영혼을 재현' 등의 의료·사실 오인 표현 금지. AI 내용은 창작된 추모 콘텐츠임을 명시한다.
- 어려움을 강하게 호소하는 고객에게 구매 압박·AI 답장 추천·유료 감정 상담을 하지 않는다. 전문 지원 정보는 차분하게 안내하고, 제품을 치료 서비스로 묘사하지 않는다.

## 3. 새 화면 및 정보 구조

### 3.1 `/` — 홈
- 기존 고급스러운 SoulTrace 무드와 한/영 언어 전환 보존. 사망·추모 이미지를 전체 고객에게 강요하지 말 것.
- 히어로 한국어 제안: **'함께하는 오늘을 기록하고, 함께했던 시간을 오래 간직하세요.'**
- 기본 CTA 1: `우리 아이 기록 시작하기` → 반려동물 등록/내 기록
- 기본 CTA 2: `소중한 추억 돌아보기` → 사용자 선택 추모 진입
- 보조 CTA: `우리 아이의 편지 받아보기` → 기존 `/choose` 또는 확인된 유효 경로
- 제품 설명은 `기록하기 → 자동으로 정리된 타임라인 → 월간 회고 → 선택형 편지·기념 앨범`의 4단계로 표시.
- 실제 예시만 표시하고 합성 콘텐츠는 표시. 허위 후기·가짜 사용자 수·영구 보관 약속 금지.

### 3.2 `/my/pets` 또는 기존 Next.js 관례의 동등 경로 — 내 아이들
- 가입/로그인 이후 반려동물 0건이면 `우리 아이 등록`으로 유도. **편지 생성 없이 pet 생성 가능**.
- 아이 이름(필수), 대표 사진(선택), 종(선택), 생일/입양일(선택), 현재 상태(living/memorial/unspecified), 기타 특징(선택).
- 반려동물이 둘 이상이어도 동명·동종 구분 가능. 한 계정 아래 여러 pets.
- 기존 등록된 펫/편지 자동 표시. 유사 이름을 근거로 계정이나 펫 자동 병합 금지.
- 등록 즉시 `첫 추억 남기기` 버튼.

### 3.3 `/my/pets/:petId` — 오늘의 기억 / 기록 타임라인
- 홈 상단: 반려동물 사진, 이름, 상태 변경 설정, `사진·영상 추가`, `이야기 작성`.
- 타임라인: 날짜순 정렬, 사진·영상·글·편지 구분, 즐겨찾기, 년도 필터, 날짜 수정, 설명 수정 및 소유자 삭제.
- 첫 업로드 직후 즉시 타임라인 카드와 `오늘의 첫 기록이 저장됐어요` 피드백. **결제 요구 없음**.
- 날짜가 불명확한 과거 사진은 자동으로 그날이라고 단정하지 않는다. EXIF는 허가 범위에서만 활용.
- 3개 이상의 기록이 축적되면 **유료 AI 없이도** `이번 달 추억 카드` 기본 버전 생성(날짜/사진/문장 템플릿). 사용자가 탭해야 생성.
- 다운로드/내보내기는 사용자의 기본 기록에 대해 가능해야 함. 저장 제한과 서비스 종료 처리 공개.

### 3.4 추모 모드 (`/my/pets/:petId/memorial` 또는 뷰 전환)
- 운영 상태는 별도 데이터 모델 `life_status`로 저장. **'추모 모드'를 한 번 켰다고 데이터나 기존 편지 제거 금지**.
- 화면 문구: `그리운 날, 편하게 찾아오세요.` / `함께했던 시간을 있는 그대로 간직할게요.`
- 비공개 편지 쓰기(보호자가 아이에게), 기억 속 AI 편지 만들기(선택), 가족 공유(선택), 인쇄/PDF(선택).
- 반복 방문/연속 접속 보상, 감정 상태 기반 강제 업셀, 정해진 날짜에 자동으로 슬픈 편지 발송 금지.
- 감정 기록은 기본 비공개, 자동 공개나 제품 간 공유 금지.

### 3.5 `/my/pets/:petId/letters` — 편지 보관함
- 기존 편지 생성·공유 코드는 보존하되, 개별 편지를 pet_id에 소유시켜 타임라인에도 표시.
- 콘텐츠 선택: `오늘의 편지`, `생일·기념일 편지`, `기억을 돌아보는 편지`.
- 사용자가 승인한 사진/추억만 AI 컨텍스트로 활용; 사용하지 않은 기억을 지어내지 않는다.
- 생성 전 AI 창작 고지·결과 샘플·예상 비용/혜택 표시. 생성 결과에 수정·재생성 한도.

### 3.6 기념 앨범 판매 시퀀스(기능 검증 후)
- 처음 1~3개의 기록을 올린 사용자를 결제 화면으로 밀어내지 않음.
- 기록 5건 또는 재방문 2회 등 *실험용 조건* 충족 시 `이번 달 기념 앨범 완성하기` 선택 제안.
- 사용자가 실제 자기 사진/기록으로 만들어진 목업을 확인 → 포함 항목과 최종 가격 확인 → 결제 → 원본 소장본 다운로드.
- 최초 검증 상품: 디지털 앨범 + 편지 **29,000~39,000원 가격 가설**. 운영 서버 설정/상품 테이블로 가격 관리하며 프런트 하드코딩 금지.
- 결제 SDK를 그냥 연결하는 것으로 끝내지 말고 PG 실계약, 승인 서버 검증, 중복 결제 방지, 환불·제작 실패 처리, 영수증·약관을 먼저 구현.
- 월 구독 3,900~5,900원은 사용률/원가 검증 후에만 P2에서 별도 테스트. 무료 보관물을 잠그지 말 것.

## 4. 백엔드·DB/인증 (반드시 안전하게)

### 4.1 안전한 진화 경로
1. 운영 Supabase 스키마에 **실제 적용된** migrations/테이블/트리거/정책 확인(읽기 전용). Git에 SQL이 있다고 적용됐다는 뜻 아님.
2. 사용 중인 데이터와 함께 staging DB 만들고 익명화한 테스트 데이터로 백필 리허설.
3. `soul_trace_pets` 재사용/확장: status, profile_photo_ref, dates 등 선택 컬럼.
4. 사진·영상·추억이 `submission_id`에 종속된 현재 구조에 **pet_id 기준 새 API/조회 레이어**를 추가. 기존 `submission_id`는 호환/출처 정보로 유지.
5. 구 테이블의 `submission_id` NOT NULL/FK를 무작정 DROP 하지 말고 새 per-pet 기록 테이블(또는 nullable + 신규 FK) 중 안전한 방법을 선택. 기존 rows를 잃지 않는 idempotent migration 및 rollback 작성.
6. 과거 편지와 펫 연결, legacy claim 로직 유지. owner_user_id 인증 기반 접근 및 RLS 구현. 같은 이름의 펫을 추정 병합하지 않음.
7. 영구 저장과 임시 브라우저 저장을 구분하고, 사용자 승인과 검증 전 임시 데이터 삭제 금지.

### 4.2 권장 개념 모델 (실제 스키마 보고 이름 결정)
- `soul_trace_pets` = 반려동물 기준 엔터티 (owner_user_id, name, status, dates)
- `pet_memories` = per-pet timeline (id, owner, pet, kind, title, story, happened_at, visibility, origin)
- `pet_memory_assets` = 파일 메타(원본 개인 스토리지 path, MIME, size, hash, 변환본) — 기존 사진/영상 테이블 재사용 가능
- `pet_letters` = 기존 submissions에 펫 ID 연결하는 읽기 뷰/연결. 편지 원본 데이터와 편지별 prompt context 보존.
- `user_share_grants` = 가족 초대/공유 대상·만료·철회·보기/기록 작성 권한
- `product_links` = 추후 Seeed 목걸이/EB용 사용자 동의·product/link 상태만 저장; **지금은 스키마 설계만**
- `product_export_jobs` = SoulTrace 동의 기반 내보내기 상태(작업 대기/완료/실패, 목적, 승인 범위); P2.

### 4.3 안전 조건
- API 요청에서 온 owner_user_id, email, pet_id를 그대로 신뢰하지 말 것. 세션 사용자와 소유권/공유 권한 확인.
- 반려동물 사진·가족 대화·감정 일지·GPS는 기본 비공개. Supabase Storage private bucket + 짧은 signed URL, 로그/분석 이벤트에 본문 저장 금지.
- 가족 공유는 명시적 초대와 취소 가능한 권한. 비밀번호나 UUID만으로 읽기 권한을 우회하지 않도록 할 것.
- 내 자료 다운로드(가능한 원본/메타데이터)와 계정 삭제/보존 기간·복구 정책을 명확히 제공.
- `app/api/customer-data/route.ts`는 구형 기기 설정용 이메일 기반 조회 + 서버 전용 토큰 구조: 이 API를 공개 '동기화' API로 쓰지 않는다.
- 외부 연동은 **서버 간 한정 범위 데이터 전달 + 선택한 자료에 대한 명시적 동의**. 편지 일회용 handoff를 영구 권한으로 사용하지 않음.

## 5. Seeed 목걸이 및 Eternal Beam과의 경계 (현재 SoulTrace만 작업)
- **Seeed XIAO BLE nRF52840 Sense**: 목걸이에서 활동량/IMU 데이터 수집 예정. 산책 GPS는 1차적으로 휴대폰이 측정; L76K를 붙여도 단독 원격 통신이 되는 것은 아님.
- 목걸이 구매자에게 SoulTrace 기록을 자동 연결하는 것은 *추후* 기능: 구매 확인/기기 페어링→로그인→기존 pet 선택→사진/이름/승인된 애니메이션 전달→산책 summary 반영. 기존 프로필 중복 생성 금지.
- 이동하는 아이의 애니메이션은 **목걸이 제약에 맞게 변환된 디지털 자산**이어야 함. Eternal Beam에서 이미 만들어진 결과물을 사용하더라도 홀로그램 앱/기기 제어 기능을 SoulTrace로 통합하지 않음. 원본 AI 동영상이 곧 nRF52840에서 재생 가능하다고 가정 금지.
- **Eternal Beam은 홀로그램 기계 전용 독립 앱**. 이 저장소 안에 생성 엔진/렌더러/기기 관리/크레딧을 복제하거나 DB 직접 읽기 금지.
- 미래 연동: 사용자가 `SoulTrace 추억 가져오기` 동의 시 선택한 펫 및 이미지·영상만 안전한 별도 서비스 API/어댑터로 전달. 자동 전송 기본 OFF, 철회 가능. **이번 개편에서는 계약 문서만 남기고 외부 앱 코드는 수정하지 않는다.**

## 7. 수집할 퍼널 이벤트 (PII·콘텐츠·GPS 본문 금지)

- 사용자 식별은 최소화된 익명 ID; 법령·동의·개인정보 고지를 검토하고 이벤트 변경 이력 남길 것.
- 고객 전환(첫 기록 완료율, 재방문, 앨범 미리보기→결제율), 단가(AI·스토리지·결제/배송·CS 비용)를 개별 집계.
- 가격은 테스트 가설이다. 구매자 후기를 사실인 것처럼 임의 작성 금지.

## 8. 인수 시나리오(최소 18개)

1. 신규 사용자: 편지 생성 없이 반려동물 등록 가능.
2. 사진 1장 업로드 후 새로고침해도 서버 기록 유지.
3. 다른 기기 로그인 후 동일 기록 접근 가능(임시 저장과 명확히 구별).
4. 반려동물 2마리의 기록이 섞이지 않음.
5. 제3자 계정으로 다른 사용자의 pet_id API 접근하면 403/404.
6. 이전 사용자의 letter/submission 접근 및 공유 링크 정상 유지.
7. 기존 사진·영상·텍스트 기록 1건 이상이 백필 후 유실 없이 조회됨.
8. 이전 스키마/미적용 migration 환경에서도 단계적으로 복구/오류 안내.
9. 사진(1~5장)·영상(30초/50MB)의 기존 유효성 검사를 유지.
10. 잘못된 확장자/용량 파일 업로드가 차단됨.
11. 임시 브라우저 저장이 서버 영구 저장으로 잘못 표시되지 않음.
12. 사용자가 추모 모드를 켜도 편지/원본 기록이 삭제되지 않음.
13. 추모 알림은 기본 OFF, 구독/수신 없이도 기록 접근 가능.
14. 가족 초대 없이 사진·감정 기록 공개되지 않음.
15. AI 편지와 진짜 펫 메시지를 혼동하게 하는 표현 없음.
16. 미리보기 콘텐츠의 사진 원본/개인정보가 타인의 브라우저에 노출되지 않음.
17. 결제 승인 재시도 시 2중 주문/권한 중복 지급 없음(결제 구현 단계).
18. 개인 자료 export 후 재가져오기 가능한 메타데이터/링크 목록 확인.
19. 공유 동의 취소 이후 신규 자료의 외부 전송 없음.
20. 한·영, 모바일 360px, 키보드 접근성, 오류 상태 점검.
21. 기존 Eternal Beam 편지 handoff가 변경 후에도 정상 동작.
22. 메모리샵 코드·의존성이 새로 추가되지 않음.
